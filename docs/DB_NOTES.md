# DB · 남은 옛 설계 (DB_NOTES)

**이 문서는 기록이다. 고치라는 목록이 아니다.**

여기 적힌 것은 전부 **동작하는 코드**다(CLAUDE.md §4 — 동작하는 코드를 다시 쓰지 않는다).
지금 걷어내면 출시가 밀리고 새 결함이 난다. **시범운영에서 무엇을 실제로 쓰는지 본 뒤**가 싸다.

목적은 하나다 — 다음 사람이 *"이거 왜 둘이지"* 에서 시간을 쓰지 않게 하는 것.

작성 2026-08-10 (K-5).

## 3. 괜찮은 것 (2026-08-09 확인)

- **RLS 가 전 테이블에 켜져 있고 대부분 정책이 0개** = 아무도 직접 못 읽는다.
  백엔드(service role)만 통과한다. §10 과 일치한다. **문이 하나다.**
- 핵심 일곱 테이블의 모델은 §7 의 세 계층을 그대로 담고 있다.
- 인덱스는 K-4 하나 말고는 문제 없다 (2026-08-10 에 `album_bookmarks_album_id_idx` 를 넣었다).
- **FK 는 K-2 에서 정리됐다** — `albums` 의 자식 열다섯이 `ON DELETE CASCADE` 이고,
  `analytics_events` · `ai_usage_logs` 만 `SET NULL` 이다(통계는 앨범이 사라져도 남는다).

## 4. 화면 쪽에 남은 같은 성격의 것 (2026-08-09~10)

DB 는 아니지만 **"근거가 여럿"** 이라는 같은 뿌리라서 여기 적는다.

### 4-1. 서버 원문이 화면에 나올 수 있는 자리가 더 있다

K-11 은 **앨범 화면 하나만** 고쳤다 — 오류 상태에 서버가 보낸 말을 담지 않고,
`lib/albumTrouble` 에서 우리 말을 골라 낸다.

그런데 다른 화면들은 아직 `setError(cause.message)` 로 **서버 원문을 그대로** 담을 수 있다.
백엔드에는 영어 `detail` 이 여럿 있다(`You do not have permission to ...`).

- 기준은 `SCREEN_SPEC` 26차 §11 이다 — **화면에 낼 말은 한 곳에서 고른다.**
- 전수 조사는 하지 않았다. 고칠 때는 `albumTrouble` 방식을 따르고 새 파일을 만들지 않는다.
- ★ 백엔드 메시지를 영어로 두는 것 자체는 문제가 아니다. 기록으로는 영어가 찾기 쉽다.
  **화면에 나가는 것**만 막으면 된다.

### 4-2. 초대장(JoinPage)은 로그인 왕복에서 적어둔 이름을 잃는다

`카카오로 계속하기` 를 누르면 앱 밖으로 나갔다 돌아온다. 그 사이 입력칸에 적어 둔
이름이 사라진다(돌아온 뒤에는 프로필 이름으로 채워지므로 빈칸으로 남지는 않는다).

**PO 판단으로 고치지 않았다.** 나중에 한다면 반드시 이 방향이다:

> **"입력값 보존"이지 "참여 이어하기"가 아니다.**

§1 이 *"로그인했다는 이유로 참여자를 만들지 않는다 — 참여는 언제나 이름을 적고 시작한다"*
이므로, 로그인 뒤 **저절로 참여시키는 쪽으로 자라면 안 된다.**
(K-9 · K-15 가 게스트 저장·담아두기에 붙인 "하려던 일을 기억한다" 장치를
여기에 그대로 옮기면 §1 을 깨게 된다. 옮기지 않는다.)

## 5. auth 쪽 — 지우지 말고 알고만 있을 것

### 5-1. 주인 없는 계정 하나

```
f6f731e0-b1e1-4b41-ad50-bdd6033ad737   곽병준 · email null · identity 0건
```

2026-08-06 **카카오 앱 재생성 사고**의 잔재다. 연결된 identity 가 없어 아무도 이 계정으로
로그인할 수 없다.

★ **지우지 않는다.** 지울 이유가 없고, 지우면 이 사고의 흔적도 함께 사라진다.

### 5-2. 한 계정에 카카오 회원번호가 둘

```
f68ddc25...   provider_id 5025495165 · 5010497815
```

**이메일이 같아서 병합된 것이다.** 카카오 앱을 바꾸면 `provider_id` 가 전부 바뀌는데,
그때 이메일이 같으면 Supabase 가 같은 사용자로 붙여 준다.

★ **이메일 없는 카카오 계정은 병합이 안 된다.** 카카오는 이메일 제공이 선택이라
이메일 없는 사용자가 실제로 생긴다. **앞으로 같은 사고가 나면 그 사람들은 계정이 갈라지고,
갈라지면 그 사람의 앨범을 되찾아 줄 방법이 없다.**

- 확인하는 조회는 `docs/DATA_CHECKS.md` §6 에 있다.
- 지금 할 일은 없다. **카카오 개발자 콘솔에서 앱을 다시 만들지 않는 것**이 유일한 예방이다.
