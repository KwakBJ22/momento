## G-1. 🔴 캡션 저장이 안 된다 [완료 7314edb]

사용자가 자기 사진에 캡션을 달았는데 저장되지 않는다.
**캡션은 이 제품에서 인쇄까지 가는 유일한 글이다.** 저장이 안 되면 앨범이 만들어지지 않는다.

### 먼저 원인을 밝혀서 보고할 것

- 언제부터인가? 최근 커밋 중 캡션 경로를 건드린 것을 `git log` 로 찾을 것.
  후보: `1340d12`(캡션 작성자 이름 제거) · `52e3ea7`(is_mine 추가) ·
  `531da23`(PDF 재작성) · `e42038a`(코멘트→한마디) · `77dfeb2`(버튼 이름 분리)
- 어디서 끊기는가? 화면에서 저장을 누를 때 요청이 나가는가?
  요청은 나가는데 서버가 막는가? 서버는 200인데 화면이 안 바뀌는가?
- 실패가 화면에 보이는가? **조용히 실패하고 있으면 그것부터 결함이다**(§11).

### 고칠 때

- 실패를 숨기지 않는다. 저장이 안 되면 사용자가 알아야 한다.
- 권한 판정(§7)을 바꾸지 않는다 — 올린 사람 + 주최자.
- 회귀 테스트: 실제 렌더로 **캡션을 쓰고 저장되는 것**을 확인한다.
  문자열 검사만으로는 이 결함이 다시 잡히지 않는다.

## G-2. 🔴 카카오톡에서 PDF를 못 받는다 [완료 40ed064]

`카카오톡에서는 파일 저장이 막혀 있어요…` 안내가 뜬다.
이 문구는 **모든 전달 경로가 실패했을 때만** 나오는 마지막 안내다.
지금 카카오톡에서 PDF를 아예 못 받는 상태다.

E-5(`531da23`)에서 PDF 를 다시 짜면서 **서버에 올리고 그 주소로 보내는 경로**가
끊겼을 가능성이 크다.

### 확인할 것

- 생성한 PDF 를 Storage 에 올리는 경로가 아직 동작하는가?
- 올린 주소(https)로 이동시키는 경로가 살아 있는가?
- `PDF_RENDERER_VERSION 3` 으로 캐시 키가 바뀐 뒤 저장·조회가 맞물리는가?
- 어느 단계에서 실패하는지 로그(`[pdf] event=…`)로 특정할 것.

### 고칠 때

- 인앱 브라우저에서는 blob 이 아니라 **올린 파일의 주소로** 보낸다.
- 그 문구는 정말 방법이 없을 때만 나와야 한다.
- 회귀 테스트: 업로드→주소 전달 경로가 끊기면 실패할 것

## G-3. 화면 사진 배치 — 기울기와 겹침 (§9 10차) [완료 c7656a8]

**인쇄는 정돈, 화면은 리듬.** E-5 에서 기울기를 없앤 것은 **인쇄 기준**이었는데
화면까지 똑바로 서 버렸다. 화면은 스크랩북처럼 보여야 한다.

### 기울기

- **±1.5° ~ 3°.** 그 이상은 실수로 보인다.
- ★ **무작위가 아니라 사진 ID로 정해진 값.** 새로고침할 때마다 각도가 바뀌면 안 된다.
- **이웃한 사진은 반대 방향으로.** 한쪽으로 쏠리면 화면이 기울어 보인다.
- 표지 사진은 기울이지 않는다.
- **캡션은 기울이지 않는다. 글은 똑바로.**

### 겹침

- **10~15%만.** 한 번에 **두 장까지.**
- ★ **얼굴이 겹치는 자리에 오면 안 된다**(§6 — 사진이 가장 중요하다).
  얼굴 위치를 모르면 겹침을 **사진 바깥쪽 모서리에만** 둔다.
- 위로 오는 순서를 고정한다.
- 한 날짜 안에서만 겹친다. 날짜가 바뀌면 정돈된 자리에서 다시 시작한다.

### 모바일

기울이면 모서리가 화면 밖으로 나간다. **좌우에 기울기만큼 여유**를 둔다.

### ★ 인쇄는 건드리지 않는다

`.album-renderer--print` 와 `PrintPages` 는 그대로다. 기울기·겹침이 **인쇄에 새면 결함**이다.

### 회귀 테스트

- 같은 사진은 언제 그려도 같은 각도일 것
- 이웃한 사진의 각도 부호가 다를 것
- 캡션에 기울기가 없을 것
- **인쇄 렌더에 기울기·겹침이 0건일 것**

## F-1. 구경꾼 `담아두기` — `내 앨범` 세 번째 칸 (§1 9차) [완료 1ef62e2]

구경하라고 받은 링크로 앨범을 봤는데 **그 사람에게 아무 흔적이 안 남는다.**
카카오톡 대화방에서 링크를 다시 찾아야 하는데 대화방은 흘러간다.

```
내 앨범
 ├ 내가 만든 앨범
 ├ 함께 만드는 앨범
 └ 담아둔 앨범        ← 새로
```

- 저장은 `user_id + album_id` 짝 하나. 마이그레이션 하나.
- 담아둬도 **권한은 바뀌지 않는다.** 여전히 보기만 한다.
- **로그인해야 담아둘 수 있다.** 비로그인 구경꾼에게는 §1 게스트 저장 안내와 같은 방식으로.

  > **이 앨범을 내 앨범에 담아둘까요?**
  > 담아두면 다음에도 이 앨범을 찾을 수 있어요.
  > [ 담아두기 ]

- 참여자가 되면 `함께 만드는 앨범`으로 옮겨간다. **같은 앨범이 두 칸에 뜨지 않는다.**
- 담아둔 것을 뺄 수도 있어야 한다.
- 회귀 테스트: 담아둬도 쓰기 권한이 생기지 않을 것 / 두 칸에 동시에 뜨지 않을 것

## H-1. 🔴 참여자에게 `공유하기`가 보이고, 누르면 막힌다 — 역할 판정을 한 곳으로 [완료 2a3284b]

`내 앨범 → 함께 만드는 앨범`에서 앨범을 열면 하단에 `공유하기`가 있다.
참여자에게는 공유 권한이 없으므로 누르면 백엔드가 막는다(권한 없음).
**할 수 없는 행동을 보여주고 눌렀을 때 막는 것**은 §4가 가장 나쁘다고 적어 둔 경험이다.

### 원인 — 이 버튼 하나가 아니다

`frontend/src/components/AlbumView.tsx:804`

```
variant: participation ? "contributor" : "default"
```

`default`가 **주최자 네비**다. 즉 **"참여자로 확인되지 않으면 전부 주최자"**다.
`viewer_participation`은 `album_contributors`에 `user_id`가 박힌 행이 있을 때만
서버가 내려준다(`backend/app/api/album.py:2008`). 게스트로 참여했다가 나중에
로그인하면 그 행의 `user_id`가 비어 있어 값이 안 내려오고, 참여자인데 주최자 네비가 뜬다.

§1은 **"프런트는 링크 종류를 모른다 — 백엔드가 능력 플래그를 내려준다"**고 정해 뒀다.
네비만 그 규칙 밖에 있다. 지금 역할을 정하는 근거가 화면마다 다르다.

| 화면 | 무엇으로 정하는가 |
| --- | --- |
| 하단 네비 | `viewer_participation` 유무 (**없으면 주최자**) |
| 더보기 시트 | `can_edit` / `can_delete` |
| 캡션 편집 | `can_edit_caption` (사진마다) |
| 담아두기 | `!can_contribute` |

**이것이 같은 종류의 회귀가 계속 나오는 이유다.** 화면마다 자기 나름대로 역할을
다시 추측하고, 추측마다 틀리는 방식이 따로 있다.

### 고칠 것

1. **역할 판정 함수 하나.** 서버가 내려주는 `can_edit` · `can_contribute` · `can_delete`
   만 읽어 `owner | contributor | visitor` 하나를 돌려준다.
   (`frontend/src/lib/types.ts:173-175`에 세 값이 이미 있다. 새로 받을 것이 없다.)
2. **모든 화면이 그 값만 본다.** 네비 · 더보기 시트 · 담아두기 · 액션 패널.
3. ★ **`viewer_participation`을 역할 판정에 쓰지 않는다.** 그 값은 `내가 더한 것`
   숫자와 이름 띠의 재료다. 지금 두 가지가 섞여 있다.
4. ★ **fallthrough를 없앤다.** `default`라는 이름의 "나머지 전부"를 두지 않는다.
   셋 중 하나로 명시적으로 갈린다. `else = 주최자`는 틀릴 때 **항상 권한을 더 주는
   쪽으로** 틀린다. 가장 나쁜 방향이다.
5. 화면 이름·배치는 바꾸지 않는다. **누구에게 보이느냐만** 바꾼다.

### 회귀 테스트 — 여기가 핵심이다

지금 테스트는 버튼이 **있는지**만 본다. **없어야 하는지**를 안 본다.

- 세 역할 × 각 화면으로, **보이면 안 되는 것이 없을 것**
  - 참여자 화면에 `공유하기` · `표지 사진 바꾸기` · `이 앨범 지우기`가 없을 것
  - 구경꾼 화면에 `사진 추가` · `한마디` · `공유하기` · `PDF`가 없을 것
- `viewer_participation`이 `null`인 참여자(게스트로 참여 후 로그인)도
  **참여자 네비**일 것 ← 이번 결함 그 자체
- 역할을 정하는 곳이 **한 곳일 것**

## H-2. 연락처 `수정`을 누르면 빈칸이 나온다 [완료 33716ed]

`⋯` → 계정 → 연락처에서 `수정`을 눌러도 기존 값이 들어가지 않는다.
뒷자리 하나 고치려고 11자리를 다시 쳐야 한다.

### 원인 — 의도된 동작이었고, 그 판단이 틀렸다

`backend/app/services/profile_contact_service.py`

```python
def get_contact(...):
    """★ 가려진 형태만 돌려준다. 원본은 서버 밖으로 내보내지 않는다 —
    고칠 때는 새로 입력하게 한다"""
```

서버가 `010-****-5678`만 내려주니 화면에 채울 값이 없다.

가린 이유가 약하다. **자기 계정 시트에서 자기 번호를 자기가 보는 화면**이다.
얻는 것은 어깨너머 훔쳐보기 방지 정도인데, 잃는 것은 40~60대의 재입력이다.

### 고칠 것

- 서버는 **본인에게 원본을 내려준다.** 가리는 일은 화면이 한다.
  (`mask_phone` · `mask_email`을 프런트로 옮기거나 같은 규칙을 화면에 둔다.)
- 평소 표시는 지금 그대로 `010-****-5678`. **`수정`을 누르면 원본이 칸에 들어간다.**
- 전화는 원본을 넣을 때도 하이픈을 붙여 넣는다(`formatPhoneInput`).
- 손대지 않은 항목은 여전히 보내지 않는다 — PUT의 "보낸 항목만 바꾼다"는 그대로다.
- 비우고 저장하면 지워지는 것도 그대로다.
- ★ 이 값은 여전히 **본인 확인에만** 쓴다. 알림·마케팅 경로에서 읽지 않는다.

### 회귀 테스트

- `수정`을 누르면 칸에 기존 값이 들어가 있을 것 (빈칸이 아닐 것)
- 전화를 고치고 저장해도 이메일이 지워지지 않을 것
- 평소 표시가 가려진 형태일 것

## F-3. 진행 숫자가 `0장`에 오래 머문다 [완료 ab4438f]

사진 30장이면 그동안 계속 `0장`이라 멈춘 것처럼 보인다.
단계 전체가 끝날 때 세고 있기 때문이다.

- **사진 한 장이 준비될 때마다 숫자를 올린다.**
- ★ **가짜 진행률을 만들지 않는다.** 시간으로 밀어 올리지 않는다.
- ★ **단계 문구를 추가하지 않는다.** `크기를 줄이고 있어요` 같은 내부 이야기는 넣지 않는다.
  문구는 `사진을 준비하고 있어요 · N장 중 N장` 한 줄 그대로.
- 회귀 테스트: 한 장이 끝날 때마다 숫자가 오를 것

## H-3. 주석이 아직 옛 규칙을 말한다 (H-2 뒷정리) [완료 a5b6f37]

H-2 에서 규칙을 뒤집었는데 **그 규칙을 설명하는 주석 네 자리가 그대로**다.
코드는 맞고 설명만 틀린 상태다.

```
backend/app/api/auth.py:64   "연락처를 **가려진 형태로** 돌려준다"
backend/app/api/auth.py:66   "★ 원본을 내려보내지 않는다. ... 고칠 때는 새로 입력하게 된다"
backend/app/api/auth.py:78   "(화면이 가진 값은 가려진 형태라 되돌려보낼 수 없다)"
frontend/src/lib/api.ts:671  "★ 서버는 **가려진 값만** 내려준다(010-****-5678)"
```

### 왜 이것이 결함인가

이 저장소의 주석은 **판단 근거**다. 다음 사람이 그걸 읽고 결정한다.
`auth.py:66` 은 `★` 까지 붙은 강한 문장이라, 다음에 이 파일을 여는 사람은
서비스가 원본을 주는 것을 **주석을 어긴 버그로 보고 되돌린다.**
그러면 오늘 고친 빈칸이 그대로 돌아온다.

`api.ts:671` 은 더 직접적이다 — 화면 쪽 설명이 "원본은 돌아오지 않는다" 고 하는데
지금 화면은 원본을 받아 칸에 넣는다.

**테스트가 잡지 못하는 종류의 회귀다.** 테스트는 코드가 무엇을 하는지 잠그지,
다음 사람이 무엇을 믿을지는 잠그지 못한다.

### 할 것

- 네 자리를 새 규칙으로 다시 쓴다. **가리는 일은 화면이 하고, 서버는 본인에게 원본을 준다.**
- 왜 그렇게 정했는지 한 줄 남긴다 — 자기 계정 시트에서 자기 번호를 자기가 보는 화면이고,
  가려서 얻는 것보다 11자리를 다시 치는 손해가 크다.
- `PUT` 이 "보낸 항목만 바꾼다" 는 이유도 다시 쓴다. 이제 이유가 "화면이 원본을 모른다" 가
  아니라 **"손대지 않은 항목은 건드리지 않는다"** 다.
- ★ **코드는 건드리지 않는다.** 테스트도 바꾸지 않는다. 주석만이다.
- 이 김에 다른 곳에서 `가려진` · `010-****` 를 근거로 말하는 주석이 더 있는지 훑는다.
  ★ 목록이 아니라 **규칙으로** 찾는다 — 옛 규칙을 말하는 문장은 전부다.
