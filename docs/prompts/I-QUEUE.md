## I-1. 🔴 사진은 기울었는데 흰 카드는 똑바로 서 있다 [완료 81f4e55]

화면에서 사진이 기울어도 **그 사진을 감싼 흰 카드는 그대로**다. 따로 논다.
스크랩북처럼 보이라고 넣은 기울기가 오히려 어긋나 보인다.

### 원인 (확인함)

기울기는 **안쪽 `figure`** 에 걸린다.

```
components/PhotoWithMemories.tsx:47
  const frameStyle = tilt !== 0 ? { transform: `rotate(${tilt}deg)` } : undefined;
  → <AlbumPhotoFrame style={frameStyle} …>   // figure.album-photo-frame
```

그런데 **화면에서 보이는 흰 카드는 그 figure 가 아니다.**

```
AlbumRenderer.css:80   .album-renderer--screen .album-screen-photo-card__frame {
                         border: 0; box-shadow: none; background: transparent; }   ← figure 는 투명
AlbumRenderer.css:56   .album-renderer--screen .album-screen-photo-grid > .photo-block {
                         border: 1px solid …; background: var(--c-surface);
                         box-shadow: var(--sh-md);
                         transform-origin: center center; }                        ← 이쪽이 흰 카드
```

`.photo-block` 에 `transform-origin` 까지 미리 적혀 있다. 돌릴 자리를 여기로 본 흔적인데
실제 `transform` 은 안쪽에 걸렸다.

### 고칠 것 — 카드를 돌린다. 단 글은 세운다

지금 `.photo-block` 안에는 **사진 + 캡션이 같이** 들어 있다. 그대로 돌리면 캡션도 기운다.
§9 는 `글은 똑바로`, CLAUDE.md §6 은 `캡션에 카드·테두리·그림자·배경색 금지`다.
**두 규칙이 같은 것을 가리킨다 — 흰 카드는 사진만 감싸야 한다.**

```
지금                          바꿀 것
┌─────────────┐             ┌─────────────┐   ← 이 카드가 기운다
│ ┌─────────┐ │             │   [사진]     │
│ │  사진    │ │  ← 기움     └─────────────┘
│ └─────────┘ │               캡션            ← 카드 밖, 똑바로, 배경 없음
│   캡션       │  ← 안 기움
└─────────────┘  ← 안 기움
```

- 흰 카드(테두리·배경·그림자)를 **사진을 감싸는 자리로** 옮기고, 기울기를 그 카드에 준다.
- 캡션은 카드 **밖 아래**에 둔다. 기울이지 않는다. 카드·테두리·그림자·배경색 없다.
- 기울기 값 자체(`scrapbookLayout`)는 그대로다. 값이 아니라 **걸리는 자리**만 바꾼다.
- 겹침(`--photo-overlap`)이 지금대로 동작하는지 확인한다. 카드 크기가 바뀌면 폭이 달라진다.
- ★ **인쇄는 건드리지 않는다.** 기울기가 인쇄에 새면 결함이다(§9).
  다만 인쇄에서도 캡션이 카드 밖으로 나가는 것은 I-4 와 맞물린다 — 함께 본다.

### 회귀 테스트

- 화면에서 **흰 카드와 사진의 각도가 같을 것** (지금은 카드 0도, 사진 n도)
- 캡션 각도가 0일 것
- 캡션에 배경·테두리·그림자가 없을 것
- 인쇄 렌더에 기울기 0건일 것 (기존 테스트 유지)

## I-2. 🔴 `공유하기` 가 화면마다 다른 것을 연다

어디서는 시트가 뜨고 어디서는 카카오톡 대화방 선택창이 바로 뜬다.
**시트가 떠야 한다.** 무엇을 보내는지 고르지 않고 나가면 되돌릴 수 없다(§5).

### 원인 (확인함) — 진입점이 넷이고 서로 다른 것을 연다

| 자리 | 무엇을 여나 |
| --- | --- |
| `AlbumView.tsx:808` (앨범 상세) | **B-1 시트** ✅ |
| `AlbumResult.tsx:303·423` (**앨범 만든 직후**) | 옛 `share-modal` ❌ |
| `AlbumResult.tsx:287` `구경하라고 보내기` | 옛 `share-modal` ❌ |
| `CollaborationPanel.tsx:265` | **카카오 바로** ❌ |
| `PublicShareView.tsx:334` | **카카오 바로** ❌ |

B-1 에서 `AlbumView` 만 고쳤다. **가장 중요한 자리를 놓쳤다** — `AlbumResult` 는
앨범을 막 만든 직후 화면이고, 주최자가 태어나서 처음 공유하는 순간이 거기다.

§5 에 `진입점이 한 곳이어야 중복이 안 생긴다` 고 적어 둔 것이 지켜지지 않았다.
H-1 과 같은 종류다 — **한 행동에 자기 나름의 구현이 여럿**.

### 고칠 것

- **공유 시트를 공용 컴포넌트 하나로** 뽑는다(`AlbumShareSheet`). 지금 `AlbumView` 안에
  인라인으로 들어 있는 것을 꺼내는 것이다. 새로 만드는 것이 아니다.
- 위 네 자리가 **모두 그 하나를 연다.**
- 옛 `share-modal`(링크 복사 / 다른 앱으로 공유 / 카카오톡 공유)을 **없앤다.**
  그 세 버튼은 무엇을 보내는지 말하지 않는다 — B-1 이 고치려던 바로 그 문제다.
- 시트 구성은 §5 그대로: `함께 만들자고 보내기` / `구경하라고 보내기` / `링크 복사`,
  각각 설명 한 줄.
- ★ **주최자에게만 보인다.** H-1 에서 만든 `resolveAlbumRole` 로 판정한다.
  화면마다 다시 추측하지 않는다(§11).

### 회귀 테스트

- 네 자리 **어디서 눌러도 같은 시트**가 열릴 것
- 어느 자리도 카카오톡을 **바로** 열지 않을 것
- 옛 `share-modal` 이 코드에 남아 있지 않을 것
- 주최자가 아니면 어느 자리에도 없을 것

## I-3. PDF 를 누르고 나면 아무 표시가 없다

`파일로 저장하기(PDF)` 를 누르면 **한참 아무 일도 일어나지 않다가**
브라우저·안드로이드의 다운로드 알림이 뜬다. 그게 첫 신호다.

### 원인 (확인함)

```
AlbumMoreSheet.tsx:64   onClick={() => { onClose(); onExportPdf(); }}
```

**시트를 먼저 닫는다.** 진행 표시(`PDF 만드는 중...`)는 그 시트 안의 버튼 라벨이라
같이 사라진다. 그 뒤로 완료까지 화면에 아무 변화가 없다.

### 고칠 것

- 시트를 닫아도 **앨범 화면에 진행 표시가 남는다.** 만드는 동안 계속 보인다.
- 끝나면 **우리 문구로** 알린다. 시스템 알림을 유일한 신호로 두지 않는다.
- 문구는 사용자 말로. 내부 사정을 말하지 않는다(§10).

  > 만드는 중 — `앨범을 파일로 만들고 있어요`
  > 끝났을 때 — `앨범 파일이 준비됐어요`

- ★ **가짜 진행률을 만들지 않는다**(F-3 과 같은 규칙). 몇 %인지 모르면 말하지 않는다.
- ★ 실패하면 실패라고 말한다. 조용히 끝나지 않는다(§11).
- 카카오톡 웹뷰에서 주소로 여는 경로(G-2)는 그대로다. 건드리지 않는다.

### 회귀 테스트

- 시트를 닫아도 진행 표시가 남을 것
- 끝났을 때 우리 문구가 뜰 것 / 실패했을 때 실패가 보일 것

## I-4. 🔴 열람용 PDF 손질 (§9)

실물 8쪽을 받아 한 장씩 봤다. 아래는 **본 것**이다.

### 4-1. 마지막 8쪽이 완전히 빈 페이지다

아무것도 없다. 지운다. **빈 페이지가 나오는 조건**을 찾아 막는다
(한 장 더 만들어 놓고 안 채운 것으로 보인다).

### 4-2. 표지 (1쪽)

- **사진이 아래에서 잘린다.** 페이지 밖으로 넘쳐 잘린 것이다.
  표지 사진은 **페이지 안에 온전히** 들어와야 한다.
- 표지 사진에만 프레임이 없다. 다른 쪽과 같은 프레임을 준다.
- 위쪽 절반이 비어 있다. 제목·날짜·사진을 페이지에 고르게 앉힌다.
- **`우리앨범` 로고가 작고 어둡다.** 표지에서 이 서비스를 알아볼 유일한 자리다.
  ★ 항상 **색이 들어간 `우리`+`앨범` 락업**으로, 표지에서는 **크게**(§9).
- 날짜 → **`2018년 11월 18일 ~ 20일`**. 년·월을 두 번 쓰지 않는다.

### 4-3. 날짜 머리글이 매 쪽 반복된다

지금 매 쪽 위에 이렇게 나온다.

```
        2018년 11월          ← 매번 같다. 필요 없다
   2018.11.18 (사진 1장)     ← 괄호도 필요 없다
```

- **`2018년 11월` 줄을 없앤다.** 표지에 이미 있다.
- **`(사진 N장)` 을 없앤다.** 세는 것은 앨범이 할 일이 아니다.
- 남는 것은 **날짜 하나**다 — `11월 18일`.
  해가 바뀌는 앨범이면 그 해 첫 날짜에만 `2018년`을 붙인다.

### 4-4. 가로 사진의 캡션이 멀리 떨어진다

5쪽이 가장 심하다. 가로 사진 한 장인데 **위아래로 크게 비고**, 캡션은 한참 아래
카드 바닥에 붙어 있다. 사진과 캡션이 남남으로 보인다.

- 카드 높이를 고정하지 않는다. **사진 크기에 맞춰 줄어든다.**
- 캡션은 **사진 바로 아래**다. I-1 의 "카드는 사진만 감싼다"와 같은 구조다.
- 한 장짜리 쪽이 페이지를 억지로 채우지 않는다. 남는 여백은 남겨 둔다.

### 4-5. 글자가 전반적으로 작다

A4 로 인쇄해서 손에 들고 읽는 문서다. 화면 크기 감각으로 정하면 작다.
- 캡션 · 날짜 이야기 · `우리의 이야기` 본문 크기를 올린다.
- ★ **키우는 기준은 A4 실측**이다. 화면에서 보고 정하지 않는다.
- 사진이 가장 크다는 순서(§6)는 그대로다. 글이 사진을 이기면 안 된다.

### 4-6. 브랜드 쪽(7쪽)

- 위쪽 절반이 비어 있다. 내용을 페이지 가운데로.
- 로고가 작다. 이 쪽은 **브랜드를 보여주는 쪽**이라 크게.
- 문구 둘째 줄 앞에 공백이 하나 들어가 있다 — `  우리 가족의 앨범도…`. 정리한다.

### 지킬 것

- **A4 한 장에 사진 4장 이하**(§9). 지금 지켜지고 있다. 깨지 않는다.
- 사진은 자르지 않는다(`contain`).
- 인쇄용(200×200) 은 이번 범위가 아니다. **열람용만** 손댄다.
- ★ 화면(`AlbumRenderer` screen)을 건드리지 않는다. 인쇄 경로만이다.

### 회귀 테스트

- 마지막 쪽이 비어 있지 않을 것
- 표지 사진이 페이지 안에 온전히 들어올 것
- 한 쪽에 `(사진 N장)` · 중복된 `YYYY년 MM월` 이 없을 것
- 가로 사진과 캡션 사이 간격이 세로 사진과 같을 것
- 한 쪽에 사진 5장 이상이 오지 않을 것 (기존 테스트 유지)
