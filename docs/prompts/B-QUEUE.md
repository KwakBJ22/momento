## B-1. 공유하기 시트 재구성 (§5) [완료 <B1>]

### 지금 상태

`공유하기` 를 누르면 카카오톡 대화방 선택창이 바로 뜬다.
보내는 목적이 두 가지로 다른데 구분이 없다.

### 먼저 확인해서 보고할 것

A-7(`511a087`) 에서 발급 쪽까지 손댔는지 확인할 것.

- `create_share_link` 에 종류 인자가 들어갔는가?
- "구경하라고 보내기" 가 실제로 `kind='view'` 링크를 발급하는가?
- 프로덕션 `share_links` 에 `kind='view'` 행이 생겼는가?

★ 발급이 여전히 contribute 하나뿐이면, 시트를 아무리 예쁘게 갈라도 두 버튼이 같은
링크를 보낸다. 그것부터 고쳐야 한다.

### 시트 구성

`공유하기` → 바로 카카오톡을 띄우지 않고 시트를 연다.

```
┌──────────────────────────────────┐
│  함께 만들자고 보내기              │
│  받는 사람이 사진과 한마디를        │
│  더할 수 있어요                   │
├──────────────────────────────────┤
│  구경하라고 보내기                 │
│  받는 사람은 보기만 해요           │
├──────────────────────────────────┤
│  링크 복사                        │
└──────────────────────────────────┘
```

- 두 항목은 **설명 한 줄을 함께** 보여준다. 이름만으로는 차이를 모른다.
  40~60대가 잘못 보내면 되돌릴 수 없다.
- 각 항목을 누르면 그때 카카오톡 공유가 열린다.
- `링크 복사` 의 기본은 **구경하라고**(더 안전한 쪽). 복사 후 무엇을 복사했는지 알린다 —
  "구경용 링크를 복사했어요".
- 기존 시트 껍데기(`AlbumMoreSheet` · `album-inline-action`)를 재사용한다.
  새 컴포넌트를 만들지 않는다.
- 주최자에게만 보인다.

### 카카오 공유 카드

두 링크의 카드 문구가 달라야 한다. 받는 사람이 무엇을 받았는지 알아야 한다.

| 링크 | 카드 제목 | 버튼 |
| --- | --- | --- |
| 함께 만들자고 | `함께 앨범을 만들어요` | `함께 만들기` |
| 구경하라고 | `앨범을 함께 봐요` | `앨범 보기` |

### 회귀 테스트

- `공유하기` 가 카카오톡을 바로 열지 않을 것
- 시트 항목이 3개이고 각각 설명 줄이 있을 것
- 두 항목이 서로 다른 종류의 링크를 발급할 것
- 주최자에게만 보일 것

### 지킬 것

발급 확인 결과를 **먼저 보고**할 것. 발급이 안 갈라져 있으면 그것부터 고친 뒤 시트를 만든다.

## B-2. 전역 하단 네비 3칸 + "내 설정" 제거 (§4) [완료]

지금 랜딩(로그인)·사진 고르기·내 앨범의 하단 네비가 4칸이다.
`[처음으로][내 앨범][새 앨범][내 설정]`

- 3칸으로 줄인다 — `[처음으로][내 앨범][새 앨범]`
- `내 설정` 을 없앤다. 화면이 없고 계정 시트를 열 뿐인데, 헤더 `⋯` 가 같은 시트를 열어
  한 화면에 같은 진입점이 두 개다(§3).
- 계정 진입점은 헤더 `⋯` 하나로 남긴다. 잃는 기능이 없어야 한다.
- 앨범 계열 화면의 3칸 네비(§4 역할별)는 건드리지 않는다.

**회귀 테스트** — 전역 네비가 3칸일 것 / 계정 진입점이 화면당 하나일 것

---

## B-3. 참여·공유 화면 네비를 §4 표대로 (§4)

지금 참여 화면 네비가 4칸이다 — `[앨범][사진 추가][한마디][내 앨범 만들기]`

§4 표대로 맞춘다.

| 역할 | 1 | 2 | 3 |
| --- | --- | --- | --- |
| 주최자 | 사진 추가 | 한마디 남기기 | 공유하기 |
| 참여자 | 사진 추가 | 한마디 남기기 | 내 앨범 만들기 |
| 구경꾼 | *(칸 없음 — 2칸)* | 한마디 남기기 | 내 앨범 만들기 |

- 구경꾼은 2칸이다. 사진 추가·공유하기는 권한이 없으므로 보이면 안 된다.
- `앨범` 처럼 스크롤·이동으로 되는 것에 칸을 쓰지 않는다.
- 사진 추가는 강조하고, 3번째 칸은 1번과 **다른 방식**으로 강조한다(§4).

**회귀 테스트** — 역할별 칸 수와 항목이 §4 표와 같을 것 /
구경꾼 화면에 사진 추가·공유하기가 없을 것

---

## B-4. 더보기 시트 순서 (§5)

지금 `회원 탈퇴` 가 `로그아웃` 옆에 있다. 성격이 완전히 다르다.

§5 표의 순서로 맞춘다.

```
(최상단) 계정 — 사진·이름·이메일
표지 사진 바꾸기 / 함께한 사람 [N명] / 파일로 저장하기(PDF) / 새 앨범 만들기
(참여자) 여기에 없는 것
로그아웃
이 앨범 지우기
회원 탈퇴
```

- 되돌릴 수 없는 것(`앨범 지우기` → `회원 탈퇴`)이 **맨 아래**다.
- 지우기·탈퇴는 **빨간 글자만**. 배경을 채우지 않는다.
- 역할별 노출은 §5 표 그대로.

**회귀 테스트** — 항목 순서 / 회원 탈퇴가 마지막일 것

## B-5. 푸터 — 사업자 정보를 "회사 정보" 안으로 (§6)

홈 화면 하단에 회사 소개를 늘어놓지 않는다.

```
우리앨범
이용약관 · 개인정보처리방침 · 회사 정보
```

- 사업자 정보(상호·대표자·사업자등록번호·주소·문의)를 `회사 정보` 안으로 옮긴다.
  법적 표시 의무는 "찾을 수 있는 곳에 있으면" 충족된다.
- `회사 정보` 는 **새 페이지를 만들지 말고 시트로** 연다(§11). 이미 있는 시트 껍데기 재사용.
- 문서에 없는 항목을 지어내지 않는다. 통신판매업 신고번호는 유료 판매 전까지 넣지 않는다.
- 공유 화면 푸터는 그대로 둔다 — 구경꾼이 이 서비스를 확인할 유일한 곳이다.

**회귀 테스트** — 푸터 본문에 사업자등록번호가 없을 것 /
`회사 정보` 를 열면 5개 항목이 있을 것

## B-6. 주 버튼 4종 통일

같은 "주 버튼" 인데 화면마다 높이·굵기·색이 다르다.
사용자가 느끼는 "통일감 없음" 의 가장 큰 원인이다.

`btn btn--primary`(2) / `upload-form__submit`(11) / `collab-panel__primary`(3) /
`album-bottom-navigation__primary`(2) — CSS 정의도 3곳에 흩어져 있다.

- **먼저 보고할 것**: 네 가지의 실제 높이·글자 크기·굵기·색을 표로 낼 것.
  어느 값으로 통일할지는 그 표를 보고 정한다. **보고 후 멈춘다.**
- 정의를 `Button.css` 한 곳으로 모은다. `!important` 를 없앤다.
- ★ `upload-form__submit` 은 11곳이다. 치환 범위가 넓고 업로드 화면의 크기 감각이
  바뀔 수 있다. **이 하나만 마지막에 따로 커밋한다.**
- 보조·고스트·카카오 버튼은 이미 한 곳 정의다. 건드리지 않는다.

**회귀 테스트** — 주 버튼 정의가 한 곳일 것 / 화면별로 다른 높이·굵기가 없을 것

## B-7. 모달 껍데기 2종을 시트 계열로

`auth-modal`(로그인) · `app__withdraw`(회원 탈퇴) 두 개만 옮긴다. 다섯 종 전부가 아니다.
딤·Esc·스크롤 잠금이 제각각이라 카카오 웹뷰에서 갇히는 사고가 났던 유형이다.

- 기존 `album-inline-action` 계열(공용 딤·스크롤 잠금·딤 클릭 닫기)로 옮긴다.
- ★ 로그인 모달은 포커스 복원·Esc·body 스크롤 잠금이 **이미 테스트로 잠겨 있다.**
  옮기면서 잃기 쉽다. 그 테스트가 그대로 통과해야 한다.
- `CollaborationPanel` 내부 모달 2곳과 `share-modal` 은 이번에 건드리지 않는다.

**회귀 테스트** — 두 모달이 공용 딤·스크롤 잠금을 쓸 것 / 기존 접근성 테스트 유지
