# Momento 디자인 시스템

작성 2026-08-01. 이 문서가 시각 규칙의 단일 출처다.
(이전 `Momento_Album_Design_System_v1.md` 는 앨범 렌더러만 다뤘고 코드가 따르지 않았다. 폐기한다.)

## 원칙

1. **정돈이 먼저, 아름다움은 그다음.** 색이 미묘하게 다 다르면 사람은 "다른 색"이 아니라
   "정돈되지 않았다"로 읽는다. 일관성이 완성도의 8할이다.
2. **선택지를 줄인다.** 둥글기가 10종이면 다음 사람이 11번째를 만든다. 4종이면 그 안에서 고른다.
3. **hex 를 직접 쓰지 않는다.** 모든 색은 `tokens.css` 의 변수로만 쓴다.
4. **사진이 주인공이다.** UI 는 사진을 방해하지 않는다. 채도 높은 색과 강한 그림자를 피한다.
5. 사용성 > 속도 > 감성 > 시각적 완성도. 미관을 위해 사용성을 희생하지 않는다.

## 1. 색

`frontend/src/styles/tokens.css` 가 실제 정의다. 아래는 용도 설명이다.

### 배경

| 토큰 | 값 | 쓰는 곳 |
| --- | --- | --- |
| `--c-bg` | `#fffdfb` | 앱 기본 배경. 거의 흰색이라 사진이 살아난다 |
| `--c-surface` | `#ffffff` | 카드, 사진 프레임 |
| `--c-bg-soft` | `#fdf7f5` | 은은하게 구분되는 영역 |

### 선

| 토큰 | 값 | 대비(흰 표면) | 쓰는 곳 |
| --- | --- | --- | --- |
| `--c-border` | `#e0caca` | 1.56:1 | 입력 필드·버튼 등 컴포넌트 자체의 테두리 |
| `--c-border-strong` | `#c9a9a9` | 2.16:1 | 흰 배경 위 카드·패널의 경계선, 섹션 구분선, 입력 포커스 |

#### 테두리 토큰 사용 규칙

흰 배경(`--c-surface`) 위에서 `--c-border`(1.56:1)는 사실상 보이지 않아 **렌더링 오류처럼**
읽힌다. 따라서 무엇의 테두리인지로 나눈다:

- **`--c-border`** — 입력 필드·버튼처럼 **컴포넌트 자체**의 테두리. 내부 대비(글자·아이콘)와
  형태로 이미 인지되므로 이 대비로 충분하다.
- **`--c-border-strong`** — **카드·패널의 경계선, 섹션 구분선** 등 흰 배경 위에 얹혀 "여기부터
  다른 영역"을 알리는 선. 안 보이면 경계가 사라져 오류처럼 보인다.

> 판단 기준: "이게 **카드/섹션의 경계**인가?" → `--c-border-strong`. "이게 **입력/버튼 컴포넌트**의
> 테두리인가?" → `--c-border`. 색만 바꾸고 두께·radius는 토큰 규칙(§3)을 따른다.

### 글자 — 4단계 위계

| 토큰 | 값 | 대비 | 쓰는 곳 |
| --- | --- | --- | --- |
| `--c-text` | `#2d2d2d` | 13.57:1 | 본문·제목 |
| `--c-text-soft` | `#5a5150` | 7.59:1 | 보조 본문 |
| `--c-text-muted` | `#7d716f` | 4.64:1 | 설명·캡션 |
| `--c-text-subtle` | `#7e726f` | 4.58:1 | 비활성·placeholder (40대 이후 타겟: 3.00→4.5:1 상향) |

### 브랜드 — 웜코랄

**브랜드 색과 액션 색을 분리한다.** `#ff6b6b` 는 채도 100%·명도 71% 라 밝다.
흰 글자를 얹으면 2.78:1 로 큰 글자 기준(3:1)도 미달한다.

| 토큰 | 값 | 대비 | 쓰는 곳 |
| --- | --- | --- | --- |
| `--c-brand` | `#ff6b6b` | — | **아이덴티티.** 로고·아이콘·선택 테두리·하트. **글자를 얹지 않는다** |
| `--c-brand-action` | `#b34a46` | 흰 글자 5.27:1 | 주 버튼 배경 |
| `--c-brand-action-hover` | `#993d3a` | 6.81:1 | hover·pressed |
| `--c-brand-text` | `#8a2c2c` | 8.48:1 | 흰 배경 위 코랄 계열 글자 |
| `--c-brand-soft` | `#fff0f0` | — | 선택 상태 배경 |

**코랄은 면적을 작게 쓴다.** 사진이 주인공인데 강한 코랄이 넓게 깔리면 시선을 뺏는다.
로고·CTA·선택 상태·하트에만 쓰고 배경은 거의 흰색을 유지한다.

#### `--c-brand-soft` 사용 규칙

`--c-brand-soft` 는 **작은 브랜드 액센트**용이다. 다음 4가지에만 쓴다:

1. **선택·활성 상태** — 선택된 칩/카테고리/탭, `is-active`, 눌린 반응(`is-pressed`)
2. **hover/focus** — 메뉴 항목 hover, 포커스 배경
3. **스켈레톤·이미지 플레이스홀더** — 로딩 셔머, 사진이 아직 없는 자리
4. **배지·알림** — "N명이 다녀갔어요" 배지, 인라인 안내(notice)

**쓰지 않는 곳**: 중립 영역 배경, 섹션/패널 배경, **다이얼로그 배경**, **앨범 본문(사진·챕터·에필로그) 배경**.
이런 곳엔 `--c-surface`·`--c-bg`·`--c-bg-soft` 또는 여백·구분선으로 처리한다.

> **앨범 본문에는 배경색 자체를 쓰지 않는다.** 웹/공유/PDF가 같은 `AlbumRenderer`를 쓰므로 배경색은
> 인쇄 시 전 페이지에 잉크로 찍혀 원가·품질에 직접 영향을 주고, 사진(주인공)과 경쟁한다. (CLAUDE.md §6)

### 상태

| 토큰 | 값 | 대비 |
| --- | --- | --- |
| `--c-danger` | `#a3231f` | 7.45:1 |
| `--c-success` | `#2f6b44` | 6.35:1 |

**삭제는 배경을 채우지 않는다.** 브랜드가 붉은 계열이라 빨간 배경 버튼은 브랜드 색과 헷갈린다.
글자와 테두리로만 표현하고, 실제 파괴적 동작은 확인 모달로 막는다.

`--c-kakao` `#fee500` / `--c-kakao-text` `#191600` 은 카카오 브랜드 규정상 고정값이다.
카카오 버튼 외에 쓰지 않는다.

### 대비

본문 글자는 배경 대비 4.5:1 이상을 지킨다.
`--c-text-subtle` 은 작은 글자에 쓰지 않는다 (비활성 상태 전용).

## 2. 간격

**4의 배수만 쓴다.** `--s-1`(4) `--s-2`(8) `--s-3`(12) `--s-4`(16) `--s-6`(24) `--s-8`(32) `--s-12`(48)

- 요소 내부 여백: `--s-2` ~ `--s-4`
- 요소 사이: `--s-3` ~ `--s-6`
- 구역 사이: `--s-8` ~ `--s-12`

| `--sh-lg` | 모달, 바텀시트 |

## 5. 글자

### 폰트 — Pretendard

기존에는 웹폰트 없이 기기 기본 글꼴에 의존했다(`Apple SD Gothic Neo, Malgun Gothic, sans-serif`).
그 결과 기기마다 글자가 다르게 보였고, 주 채널인 **안드로이드 카카오톡 웹뷰에서 가장 나쁜 글꼴**이 나왔다.

`--font` 토큰으로 **Pretendard** 를 쓴다. 어느 플랫폼에서든 같은 글자가 나온다.


**40대 이후 타겟 기준: 본문·보조 16px, 라벨 14px 하한**(노안 대비 최소 크기).

| 토큰 | 크기 | 쓰는 곳 |
| --- | --- | --- |
| `--t-xs` | 0.875rem (14px) | 라벨, 메타 (하한) |
| `--t-sm` | 1rem (16px) | 보조 본문, 버튼 |
| `--t-base` | 1rem (16px) | 본문 |
| `--t-lg` | 1.15rem | 소제목 |
| `--t-xl` | 1.5rem | 화면 제목 |
| `--t-2xl` | 2rem | 앨범 제목 |

> ⚠️ 현재 앱 상당수가 이 토큰 대신 rem 값을 직접 박아 써서, 토큰 상향의 실제 반영은 좁다
> (`var(--t-sm)` 사용 4곳, `var(--t-xs)` 0곳). 40대 타겟 크기를 화면 전반에 적용하려면
> 하드코딩 크기를 토큰으로 옮기는 별도 작업이 필요하다.

굵기는 `--w-normal`(400) / `--w-medium`(600) / `--w-bold`(750) 셋만.
행간은 제목 `--lh-tight`(1.25), 본문 `--lh-base`(1.6).

## 6. 아이콘

`lucide-react` 만 쓴다. 다른 아이콘 세트를 섞지 않는다.

크기는 **3종만**: `16`(인라인·보조) / `20`(기본) / `24`(강조·빈 화면).
현재 코드에 14·15·17·18 이 섞여 있다. 가장 가까운 값으로 정리한다.

`stroke-width` 는 lucide 기본값(2)을 쓴다. 색은 텍스트 토큰을 따른다.

## 7. 컴포넌트 규칙

### 버튼

역할은 **4종뿐**이다. 화면마다 새 버튼 클래스를 만들지 않는다.

| 종류 | 배경 | 글자 | 쓰는 곳 |
| --- | --- | --- | --- |
| `primary` | `--c-brand` | `--c-surface` | 화면당 **하나**. 그 화면의 목적 |
| `secondary` | `--c-surface` + `--c-border` | `--c-text` | 보조 동작 |
| `ghost` | 투명 | `--c-text-muted` | 취소, 뒤로, 낮은 비중 |
| `danger` | 투명 + `--c-danger` 글자 | `--c-danger` | 삭제, 탈퇴 |

- 카카오 공유 버튼만 `--c-kakao` 배경 + 검정 글자로 예외를 둔다.
- 높이 최소 `--tap-min`(44px). 모바일 터치 타깃 기준이다.
- 둥글기 `--r-md`, 글자 `--t-sm` `--w-medium`.
- **한 화면에 primary 가 둘이면 사용자는 무엇을 눌러야 할지 모른다.**

### 입력

- 테두리 `--c-border`, 포커스 시 `--c-border-strong`.
- 둥글기 `--r-md`, 안쪽 여백 `--s-3`.
- 글자 크기는 그 자리를 대체하는 텍스트와 같게. (제목을 편집하면 제목 크기로)
- placeholder 는 `--c-text-subtle`.

### 카드

- 배경 `--c-surface`, 테두리 `--c-border`, 둥글기 `--r-lg`, 그림자 `--sh-md`.
- 안쪽 여백 `--s-4`.

### 모달·바텀시트

- 배경막 `rgba(61, 53, 48, 0.5)`.
- 둥글기 `--r-lg`, 그림자 `--sh-lg`.
- ESC 로 닫히고, 포커스가 갇히고, 닫으면 원래 자리로 돌아온다.
- **스크롤 잠금과 모달 렌더는 반드시 함께 움직인다.** 하나만 걸리면 화면이 멈춘 것처럼 보인다.

## 8. 하지 말 것

- CSS 에 hex 값 직접 쓰기
- 토큰에 없는 간격·둥글기 값 쓰기
- 화면 전용 버튼 클래스 새로 만들기
- 한 화면에 primary 버튼 둘
- 불필요한 애니메이션. 상태 변화를 알리는 것 외에는 넣지 않는다
- 사진 위에 그라데이션·오버레이로 색을 입히기

## 9. 색상 통합 이력

정리 전 CSS 에 **고유 색 192개**가 하드코딩돼 있었다.
흰색 계열 6종, 배경 베이지 3종, 진한 텍스트 4종, 갈색 4종이 미묘하게 달랐다.

CIE Lab 색 거리로 19개 토큰에 배정했다. 191색 중 177색은 ΔE ≤ 12 라
**눈에 띄는 변화 없이** 통일된다. 나머지 14색은 사용 빈도가 1~4회인 예외 값이다.

전체 매핑표는 `docs/DESIGN_SYSTEM_COLOR_MAP.md` 에 있다.
