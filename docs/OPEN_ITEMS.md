## 3. 기술 부채

| | 무엇 |
| --- | --- |
| T1 | `onTop` 이 넘겨도 아무 일 안 하는 죽은 값으로 남음 (A11에서 지웠는지 확인 필요) |
| T2 | `noindex` 가 없다. `/s/<토큰>` · `/join/<토큰>` · `/album/…` 은 검색에 안 뜨게 해야 소개 페이지에 "검색에 안 떠요"를 쓸 수 있다 (첫 화면·`/about` 은 색인되어야 함) |
| T3 | `search_users` 가 회원 1명당 6회 돈다(Auth 1 + 카운트 3 + 앨범·참여자 2). 40명이면 240회. 수백 명이면 관리자 목록이 멈춘다 |
| T4 | `list_user_albums` 가 회원 상세를 열 때마다 `_build_blocked_items`(5000행 스캔 + 오류 대시보드) 전체를 돈다 |
| T5 | 앨범 주인 판정이 갈렸다 — 관리자는 `owner_id`, 탈퇴·앨범 상한은 `created_by OR owner_id`. 지금 운영 데이터는 0건 차이지만 게스트 앨범이 늘면 갈린다 |
| T6 | `test_admin_users_response_requires_status` 는 `search_users` 를 대역으로 갈아끼워 **계약만** 검사한다. 진짜 서비스에서 `status` 를 빼도 통과한다 |

## 규칙 (이번에 정한다)

1. **대화에서 "나중에" 라고 말한 것은 그 자리에서 이 파일에 적는다.** 안 적으면 없는 것이다.
2. **작업 커밋에 이 파일 갱신을 함께 담는다.** 워크트리에만 두지 않는다.
3. **작업을 시작하기 전에 이 파일의 0번(확인 대기)부터 본다.**
4. 항목을 지울 때는 지운 이유(끝남/취소/보류)를 남긴다.
